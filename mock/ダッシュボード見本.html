PLM環境ダッシュボード

1つのページに、Webパーツを6つ並べています。うち3つがリストです。 カードと行を押すと、右からパネルが出ます。 追加・編集・削除は、そのパネルの中で行います。
客先へ渡すときは、列を絞ったビューを開き、ブラウザの印刷でPDFにします。

丸い番号の部分を、何で作るのか

使う機能この見本で何をしているか承認
1ギャラリー ビューの書式設定（formatter） 1件を1枚のカードにする。段階と状態を色の丸で出す。画像の列から構成図の縮小版を出す。最終更新からの日数を計算し、30日を超えたら色を変える。カードのボタンで編集画面を開く要らない
2リスト ビューの書式設定（rowFormatter・groupProps） 1行を1本の帯にする。帯の左の位置と長さを、発生日と完了日から計算する。環境IDでグループ化し、グループの見出しに月の目盛りと件数を出す。帯にカーソルを当てるとカードで内容を出す要らない
3ビューの絞り込みと並べ替え 期日が今日より前で、状態が解決ではないものだけを出す。書式設定は使わない要らない
4フォームの構成（sections・fieldsettings） 詳細と編集のパネルの中身を決める。列をセクションに分け、見出しを付ける。環境IDは直せない列にする。 パネルの枠と保存の動きは SharePoint が用意する要らない
5行のボタン（customRowAction） 行の「···」から詳細・編集・削除を開く。状態は行の中でその場で直す（inlineEditField）。 削除の確認とごみ箱は SharePoint の標準の動き要らない
6テキストのWebパーツ 使い方と書き方の決めごとを、ページの先頭に置く。台帳がだめになる原因は、 書き方が人によって変わることなので、規則を画面の中に置く要らない
7ドキュメント ライブラリと人のWebパーツ 手順書の置き場所と、誰に聞けばよいかを同じページに出す。どちらも並べるだけで、JSONが要らない 要らない

2段では、どうしてもできないこと

  • カードを押して、下の時系列を連動して絞り込むこと。Webパーツ同士をつなぐ標準の仕組みがありません。人が時系列側の「環境」を選び直します
  • 目盛りを1本だけ上に固定すること。目盛りはグループの見出しごとに描くので、環境の数だけ出ます
  • 拡大と縮小、帯をつまんで期間を変えること。書式設定は表示だけを変える仕組みで、操作を作れません
  • 2つのリストをまたいで数えること。環境のカードに「出来事7件」と出せません。件数は時系列の側のグループの見出しに出します
  • ビューで列を外しても、権限の制限にはなりません。客先へ渡すPDFからは外せますが、 リストを開ける人はほかのビューでその列を見られます。だから、パスワードのような値は どの列にも入れません（機密の保管は今回作りません）

この見本を描く前に、公式文書で確かめたこと

  • 書式設定で使える要素に svg と path があり、width left position を式で計算できること（書式設定の構文の一覧・2025-08-26 更新）
  • 日付の計算に Date() Number() floor addDays @now が使えること。帯の位置を日付から出せます
  • グループの見出しを groupProps の headerFormatter で作り替えられ、@group.count で件数が取れること
  • カーソルを当てたときのカードを customCardProps で作れること。行の中で値を直せる inlineEditField があること
  • 行のボタンから editProps（編集を開く）・delete（削除の確認を開く）・ openContextMenu（既定のメニューを開く）を呼べること
  • フォームは、ヘッダー・本文・フッターを JSON で構成でき、本文はセクションに列を割り当てる形であること。 「ビューを作って管理できる人なら誰でも設定できる」と書かれています（フォームの構成・2026-09-01 更新）
  • fieldsettings の readonly で、編集のフォームで直せない列にできること
  • 注意＝フォームのJSONはリストのコンテンツタイプに保存されます。コンテンツタイプが読み取り専用だと設定が当たりません
  • 新しい画面のリストのビューは、リスト・コンパクト リスト・ギャラリー・カレンダー・ボードの5つで、ガントは無いこと。ガントは古い画面のプロジェクト タスクのリストの機能です
