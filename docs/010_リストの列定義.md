# リストの列定義

リストは2つ。**環境台帳**（1行＝1環境）と**対応の経緯**（1行＝1件のトラブルか改修）。
2026-09-03 に固めた。**列は後から足せる。最初から完璧にしない。**

## 作り方の順番（ここを間違えると直せない）

1. **リストを英数字の名前で作る。**`EnvLedger` と `IncidentLog`
2. **列も英数字の名前で作る。**下の表の「内部名」で作る
3. **そのあとで、表示名を日本語に変える**

**作ったときの名前が、そのまま URL と内部名になる。**あとで表示名を変えても内部名は変わらない。
日本語で作ると内部名が `_x74b0__x5883_` のような記号の並びになり、
**書式設定の JSON から列を指せなくなる。**

`Title` の列は消せない。**表示名だけを変えて使う。**

「更新日時」と「更新者」は SharePoint が自動で持つので、列として作らない。
**カードの「最終更新から何日」は、この更新日時から計算している。**

### 列の種類の名前について

**上の表の「種類」は、列を追加する画面に出る名前そのままである。**
2026-09-04 に製品の文書で確かめた。全部で16種類あり、この案件で使うのは次の6つ。

`1行テキスト` `複数行テキスト` `選択肢` `ユーザーまたはグループ` `日付と時刻` `画像` `参照`

**複数行テキストは「プレーン テキスト」を選ぶ。**「拡張リッチ テキスト」にすると、
値に見えない書式の記号が混ざり、**カードの画面で崩れる。**

## リスト2＝対応の経緯（内部名 `IncidentLog`）

| 順 | 表示名 | 内部名 | 種類 | 必須 | 中身 |
|---|---|---|---|---|---|
| 1 | 件名 | `Title` | 1行テキスト | ○ | 何が起きたのかを1行で。`Title` の表示名を変えて使う |
| 2 | 環境ID | `EnvRef` | 参照 | ○ | **環境台帳の「環境ID」を参照する。**テキストで書き写さない |
| 3 | 種類 | `Kind` | 選択肢 | ○ | トラブル / 改修 / 構成変更 / 停止 |
| 4 | 状態 | `Status` | 選択肢 | ○ | 新規 / 対応中 / 解決 |
| 5 | 発生日 | `OccurredOn` | 日付と時刻 | ○ | **時系列の帯の左端になる** |
| 6 | 完了日 | `ClosedOn` | 日付と時刻 | | **帯の右端になる。**予定でよい。空のときは今日として描く |
| 7 | 内容 | `Detail` | 複数行テキスト | | 何が起きたのか |
| 8 | 対応したこと | `Action` | 複数行テキスト | | 分かっている範囲でよい |
| 9 | 担当 | `Assignee` | ユーザーまたはグループ | | |
| 10 | 添付 | （標準の機能） | 添付ファイル | | 画面の写しやログ |

## 選べる値について

**選択肢の列は、値をあらかじめ決めておく。**自由入力にすると表記が揺れて、絞り込めなくなる。

### 段階

**「運用」と「本番」は同じものとして扱う。値は「本番」でそろえる。**2026-09-03 に決定した。

環境名のほうは現場の呼び名なので、`AA用設計PLM運用環境` のまま残す。
**名前を変えるかどうかは関係者を巻き込む別の判断であり、台帳の整備とは切り離す。**

UAT やステージングが出てきたら、そのとき値を足す。

### 利用組織・対象システム

現時点の4環境から拾った値である。**他の環境が出てきたら足す。**

## 接続先を環境IDで書く理由

名前で書くと、名前が変わったときにつながりが壊れる。
番号で書けば、名前が変わってもつながりは残る。

## 決めたこと・変えたこと（2026-09-03）

- **リスト名を決めた。**環境台帳と対応の経緯
- **ホスト名とIPアドレスを、複数行テキストに変えた。**1行テキストには改行を入れられないため
- **担当はユーザーの列にする。**社外の担当者を書く必要が出たら、そのときテキストに変える
- **「経緯（Redmine）」の列を無くした。**対応の経緯のリストが担う
- **「機密の在りか」の列を無くした。**機密の保管は今回作らない
