# 作る順番

**一度に全部やらない。**1つ終わったら、そこで止めて連絡する。次を渡す。

貼り付ける JSON は `json/` にある。**ブラウザで開き、「Raw」を押してから全部をコピーする。**
通常の画面には行番号が付くので、そのままコピーすると壊れる。

---

## 第0段階＝権限を確かめる

**自分がリストを新しく作れるかを見る。**リストを作る操作には「リストの管理」という権限が必要で、
これは権限レベルが**フル コントロール・デザイン・編集**のいずれかに含まれる。
**チーム サイトのメンバー グループは、既定で「編集」である。**閲覧者や投稿だけでは、リストを作れない。

作れなければ、そこで止めて連絡する。**権限を増やす前提で進めない。**
いまある権限でできる範囲に、作り方を組み替える。

## 第1段階＝リストを2つ作る

1. **左のメニューから「サイト コンテンツ」を開く。**そこで**「＋ 新規」→「リスト」**を選ぶ
   → **サイトのホームに「＋ 新規」が出ないことがある。**2026-09-04 に、ホームだけを見て
     「権限が無い」と判断された。**「サイト コンテンツ」から入れば出る**
2. 「リストの作成」の画面で**「空白のリスト」**を選ぶ
3. **「名前」に `EnvLedger` と入れる。**「説明」は空でよい
4. 左のサイト ナビゲーションに表示するかどうかを選ぶ
5. **「作成」**を押す
6. できたら、リストの**設定（歯車のアイコン）→「リスト設定」**を開き、**名前を「環境台帳」に変える**
7. 同じ手順で `IncidentLog` を作り、名前を「対応の経緯」に変える

**日本語の名前で作らない。**英数字で作ってから名前を変える理由は `docs/010` にある。
**内部名は作成のときに決まり、あとから変えられない。**

**ここで止めて連絡する。**

## 第2段階＝環境台帳に列を作る

`docs/010_リストの列定義.md` の表のとおりに、**16件**の列を作る。

**表は18行あるが、作るのは16件である。**1番の `Title` はリストを作った時点で既にあり、
18番の添付は標準の機能なので、どちらも列として作らない。**2番から17番までを作る。**

### 1件ずつの作り方

1. 表の**いちばん右の列見出しの右にある「＋ 列の追加」**を押す
2. **列の種類を選ぶ**（表の「種類」の欄。名前は画面に出るとおりに書いてある）
3. 「列の作成」の**「名前」に、表の「内部名」の英数字を入れる**
4. **「保存」**を押す

### 気をつけること

- **列の名前は、必ず英数字の「内部名」で作る。**日本語で作ると、あとから直せない
- **全部作り終わってから、表示名を日本語に変える**
- `Title` の列は消せない。**表示名を「環境ID」に変えるだけ**
- **「既定の値」は、すべて空のままにする。**選択肢の列で値が入っていたら「なし」を選ぶ。
  理由＝**分からない欄を空欄のまま登録する方針だからである。**既定の値を入れると、
  確かめていない値が自動で入り、調べた結果と見分けられなくなる
- **「この列に情報が必要」（必須）は、いまはオンにしない。**第4段階で空欄のまま
  入力してもらうため、**先にオンにすると保存できず、手が止まる。**最後に設定する
- **複数行テキストは「プレーン テキスト」を選ぶ。**「拡張リッチ テキスト」だと画面が崩れる
- 選択肢の列（利用組織・対象システム・段階・状態）は、**選べる値を1行に1つずつ**入れる
- 添付は標準の機能なので、列として作らない

### 16件できたら、表示名を日本語に変える

**17件ある。**新しく作った16件に加えて、`Title` の表示名も変えるためである。

1. 列の見出しを押して、**「列の設定」**を開く
2. **「編集」**を選ぶ
3. **「名前」**を、`docs/010` の表の「表示名」に変える
4. **「保存」**を押す

**表示名を変えても、内部名は変わらない。**書式設定の JSON は内部名で列を指しているので、
日本語の表示名にしても壊れない。

**ここで止めて連絡する。**

## 第3段階＝対応の経緯に列を作る

同じ表の2つめのとおりに、**8件**の列を作る。`Title` と添付は作らない。
**「既定の値」と「必須」の扱いは、第2段階と同じである。**

**「環境ID」だけは作り方が違う。**種類を「参照」にして、環境台帳の「環境ID」を参照させる。
これで、入力するときに環境台帳から選べるようになる。

**ここで止めて連絡する。**

## 第4段階＝分かっている4件を入力する

`docs/020_環境の一覧.md` の4件を、環境台帳に入れる。

- **空欄のままでよい。**分からない欄は埋めなくてよい
- **環境IDは変えない。**`ENV-001` から `ENV-004` を、あの対応のまま使う
- **接続先は、相手の環境IDで書く。**名前で書かない
- **パスワードは、どの列にも書かない**

**ここで止めて連絡する。**

## 第5段階＝画面の書式設定を貼る（5か所）

| 貼る先 | 貼るファイル |
|---|---|
| 環境台帳のビュー「カード」 | `json/1_環境台帳_ビュー_カード.json` |
| 環境台帳のフォーム（本文） | `json/2_環境台帳_フォームの構成.json` |
| 対応の経緯のビュー「時系列」 | `json/3_対応の経緯_ビュー_時系列.json` |
| 対応の経緯のフォーム（本文） | `json/4_対応の経緯_フォームの構成.json` |
| 対応の経緯の列「状態」 | `json/5_対応の経緯_列_状態.json` |

### ビューを新しく作る

1. 画面の右上にある**「表示オプション」**を開く
2. **「新しいビューの作成」**を選ぶ
3. **ビュー名**を入れる（カード用と時系列用）
4. 「表示方法」で種類を選ぶ。**カード用は「ギャラリー」、時系列用は「List」**
5. **「作成」**を押す

### ビューの書式設定を開く

1. 作ったビューを開く
2. ビューの名前のところにあるドロップダウンを開く
3. **「現在のビューの書式設定」**を選ぶ
4. 枠の中に JSON を貼る。**「プレビュー」で確かめてから「保存」を押す**

### フォームの構成を開く

1. リストの項目を1件開く（表示のフォームが出る）
2. フォームの上のほうにある**「フォームの編集」**を開き、**「レイアウトの構成」**を選ぶ
3. パネルの**「書式を適用する対象」で「本文」**を選ぶ
4. JSON を貼って保存する
5. **フォームを閉じて、もう一度開く。**そうしないと変わったように見えない

### 列の書式設定を開く

1. 列の見出しを押してメニューを開く
2. **「列の設定」→「この列の書式設定」**を選ぶ
3. JSON を貼って保存する

**貼るたびに止めて連絡する。**5か所を一度にやらない。

## 第6段階＝ページを作る

1. サイトのページを新しく作り、名前を「PLM環境ダッシュボード」にする
2. 上から順に、Webパーツを6つ置く
   1. テキスト（使い方と書き方の決めごと。文面はこちらで渡す）
   2. リスト（環境台帳・ビューはカード）
   3. リスト（対応の経緯・ビューは時系列）
   4. リスト（対応の経緯・ビューは「手が止まっているもの」）
   5. ドキュメント ライブラリ
   6. 人（担当者）
3. 発行する

## 第7段階＝仕上げ

### バージョン履歴を有効にする（2つのリストとも）

1. **設定（歯車のアイコン）→「リストの設定」**
2. **「バージョン管理の設定」**
3. **「リスト内のアイテムを編集するごとに新しいバージョンを作成する」**を選ぶ

### 残りのビューを作る

- 「手が止まっているもの」＝**完了日が今日より前で、状態が「解決」ではないもの**に絞る
- 「客先に渡す」＝列を絞るだけで、書式設定は貼らない

### 必須の設定

**ここで初めて、`docs/010` の表で○が付いた列を必須にする。**
第4段階までは空欄のまま保存できる必要があるため、最後に回してある。

### 添付についての注意

**1件あたり 250 MB までである。**構成図の画像なら十分だが、
**動画や大きなログを入れると超える。**超えるものはドキュメント ライブラリに置き、
台帳からはリンクで指す。
