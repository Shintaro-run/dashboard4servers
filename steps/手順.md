# 作る順番

**一度に全部やらない。**1つ終わったら、そこで止めて連絡する。次を渡す。

貼り付ける JSON は `json/` にある。**ブラウザで開き、「Raw」を押してから全部をコピーする。**
通常の画面には行番号が付くので、そのままコピーすると壊れる。

---

## 第0段階＝権限を確かめる

**自分がリストを新しく作れるかを見る。**リストを作る操作には「リストの管理」という権限が必要で、
これは権限レベルが**フル コントロール・デザイン・編集**のいずれかに含まれる。
**チーム サイトのメンバー グループは、既定で「編集」である。**閲覧者や投稿だけでは、リストを作れない。

作れなければ、そこで止めて連絡する。**権限を増やす前提で進めない。**
いまある権限でできる範囲に、作り方を組み替える。

## 第1段階＝リストを2つ作る

1. SharePoint のサイトのホーム、または「サイト コンテンツ」で**「＋ 新規」→「リスト」**を選ぶ
2. 「リストの作成」の画面で**「空白のリスト」**を選ぶ
3. **「名前」に `EnvLedger` と入れる。**「説明」は空でよい
4. 左のサイト ナビゲーションに表示するかどうかを選ぶ
5. **「作成」**を押す
6. できたら、リストの**設定（歯車のアイコン）→「リスト設定」**を開き、**名前を「環境台帳」に変える**
7. 同じ手順で `IncidentLog` を作り、名前を「対応の経緯」に変える

**日本語の名前で作らない。**英数字で作ってから名前を変える理由は `docs/010` にある。
**内部名は作成のときに決まり、あとから変えられない。**

**ここで止めて連絡する。**

## 第2段階＝環境台帳に列を作る

`docs/010_リストの列定義.md` の表のとおりに、17件の列を作る。

- **列の名前は「内部名」の英数字で作る。**作ったあとに表示名を日本語へ変える
- `Title` の列は消せない。**表示名を「環境ID」に変えるだけ**
- 選択肢の列（利用組織・対象システム・段階・状態）は、選べる値まで入れる
- 添付は標準の機能なので、列として作らない

**ここで止めて連絡する。**

## 第3段階＝対応の経緯に列を作る

同じ表の2つめのとおりに、9件の列を作る。

**「環境ID」だけは作り方が違う。**種類を「参照」にして、環境台帳の「環境ID」を参照させる。
これで、入力するときに環境台帳から選べるようになる。

**ここで止めて連絡する。**

## 第4段階＝分かっている4件を入力する

`docs/020_環境の一覧.md` の4件を、環境台帳に入れる。

- **空欄のままでよい。**分からない欄は埋めなくてよい
- **環境IDは変えない。**`ENV-001` から `ENV-004` を、あの対応のまま使う
- **接続先は、相手の環境IDで書く。**名前で書かない
- **パスワードは、どの列にも書かない**

**ここで止めて連絡する。**

## 第5段階＝画面の書式設定を貼る（5か所）

| 貼る先 | 貼るファイル |
|---|---|
| 環境台帳のビュー「カード」 | `json/1_環境台帳_ビュー_カード.json` |
| 環境台帳のフォーム（本文） | `json/2_環境台帳_フォームの構成.json` |
| 対応の経緯のビュー「時系列」 | `json/3_対応の経緯_ビュー_時系列.json` |
| 対応の経緯のフォーム（本文） | `json/4_対応の経緯_フォームの構成.json` |
| 対応の経緯の列「状態」 | `json/5_対応の経緯_列_状態.json` |

### ビューの書式設定を開く

1. ビューを新しく作る（カード用と時系列用）
2. ビューの名前のところにあるドロップダウンを開く
3. **「現在のビューの書式設定」**を選ぶ
4. カードのほうは、パネルの**「レイアウトの選択」で「ギャラリー」**を選ぶ
5. 枠の中に JSON を貼る。**「プレビュー」で確かめてから「保存」を押す**

### フォームの構成を開く

1. リストの項目を1件開く（表示のフォームが出る）
2. フォームの上のほうにある**「フォームの編集」**を開き、**「レイアウトの構成」**を選ぶ
3. パネルの**「書式を適用する対象」で「本文」**を選ぶ
4. JSON を貼って保存する
5. **フォームを閉じて、もう一度開く。**そうしないと変わったように見えない

### 列の書式設定を開く

1. 列の見出しを押してメニューを開く
2. **「列の設定」→「この列の書式設定」**を選ぶ
3. JSON を貼って保存する

**貼るたびに止めて連絡する。**5か所を一度にやらない。

## 第6段階＝ページを作る

1. サイトのページを新しく作り、名前を「PLM環境ダッシュボード」にする
2. 上から順に、Webパーツを6つ置く
   1. テキスト（使い方と書き方の決めごと。文面はこちらで渡す）
   2. リスト（環境台帳・ビューはカード）
   3. リスト（対応の経緯・ビューは時系列）
   4. リスト（対応の経緯・ビューは「手が止まっているもの」）
   5. ドキュメント ライブラリ
   6. 人（担当者）
3. 発行する

## 第7段階＝仕上げ

- 環境台帳と対応の経緯で、**バージョン履歴を有効にする**
- 「手が止まっているもの」のビューを作る。**完了日が今日より前で、状態が「解決」ではないもの**に絞る
- 「客先に渡す」のビューを作る。列を絞るだけで、書式設定は貼らない

## 確認が済んでいない箇所

**下の画面の名前と押す順番は、まだ公式文書で裏を取っていない。**渡す前に確かめる。

**どれも第2段階から先で要るもので、第1段階には要らない。**

1. 列を追加する操作と、選べる列の種類の正式な日本語表記
2. 選択肢の列に値を設定する操作
3. 参照（Lookup）の列を設定する操作と、その制限
4. 添付ファイルの1件あたりの上限
5. ビューを新しく作る操作の画面（**作る権限があることは確認済み**）
6. バージョン履歴を有効にする操作（設定のページに「バージョン設定」があることは確認済み。押す順番が未確認）

**「現在のビューの書式設定」「フォームの編集 → レイアウトの構成」「列の設定 → この列の書式設定」の
3つは、公式文書で確認済みである（2026-09-03）。**

## 確認が済んだこと（2026-09-04）

| 確かめたこと | 結果 | 出典の種類 |
|---|---|---|
| リストを新規に作る画面と押す順番 | 「＋ 新規」→「リスト」→「空白のリスト」→名前→「作成」 | 製品の文書 |
| 名前をあとから変える操作 | 設定（歯車）→「リスト設定」で名前と説明を変えられる | 製品の文書 |
| リストを作れる権限 | 「リストの管理」は**フル コントロール・デザイン・編集**に含まれる。**メンバーは既定で「編集」。**投稿と読み取りには含まれない | 製品の文書 |
| 列の追加とパブリック ビューの追加の権限 | 同じ「リストの管理」に含まれる。**メンバーなら両方できる** | 製品の文書 |
| 内部名は作成のときに決まり、あとから変えられない | 「Internal names are set once at the point of creation; you cannot change them later.」**英数字で作ってから表示名を変える方法が推奨されている** | コミュニティの文書と Microsoft Q&A（**製品の文書ではない**） |
| 名前を変えても URL は変わらない | **製品の文書には記述が無い。**コミュニティの文書に「作ったあとで、きれいなURLのまま表示名を変えられる」とある | コミュニティの文書 |
